Voice Commander — Guide

How the pieces actually fit together.

1. End-to-end flow

When you press Scroll Lock and speak, the daemon runs this exact path: 

Scroll Lock ──► StreamingRecorder ──► Silero VAD ──► faster-whisper
                                                         │
                                                         ▼ transcript
                                                    VerbRouter | LLMRouter.route()
                                                         │
                                           match ◄───────┤────► no match
                                             │                    │
                                             ▼                    ▼
                                        Dispatcher           feedback.on_miss()
                                     runs pre-baked plan    (miss chime, done)
                                             │
                                             ▼
                                      primitive func
                                  (pyautogui keystroke,
                                   win32 focus, etc.)

Source: src/voice_commander/daemon.py → _process_utterance(). Normal mode uses VerbRouter.route(); say Merlin to toggle LLM mode. If the active router returns None, the daemon plays the miss chime and stops. There is no retry loop.

Normal mode uses a deterministic verb router. Merlin mode is a session-scoped spoken toggle that re-enables LLMRouter.route() for open-ended requests.

2. Primitives

Primitives are the seven atomic OS actions. They are plain Python functions in src/voice_commander/tools/primitives.py. They are the only things that actually touch Windows.

  • press(combo) — send a key combo
  • type(text) — synthesize keystrokes
  • focus(target) — bring a window forward
  • open(target) — launch an app, URL, or file
  • click(button) — left/right/middle click
  • scroll(direction, amount) — scroll wheel
  • wait(ms) — delay between steps

Every primitive has internal = true in primitives.toml. That flag makes them dispatchable but hidden from the LLM: all_llm_visible() filters internal entries out of the tool list sent to LM Studio.

3. Commands

A command is a named atomic action that calls exactly one primitive. Stored as JSON in commands.json at the repo root. 

"new_tab": {
  "description": "Open a new tab in the focused app",
  "synonyms": ["new tab", "open new tab", "open a new tab"],
  "enabled": true,
  "primitive": "press",
  "kwargs": {"combo": "ctrl+t"}
}

On startup (and after each edit from this UI), the commands/registrar.py builds a synthetic ToolEntry per command. The entry's func is a closure that constructs a one-step Plan and hands it to the dispatcher. The LLM sees the command's name, description, and synonyms (appended as Phrases: in the tool description).

4. Workflows

A workflow is a named ordered sequence of primitive or command references, optionally parameterised by {placeholder} args. Stored in workflows.json. 

"search_web": {
  "description": "Search the web via the default browser",
  "synonyms": ["search {query}", "google {query}"],
  "enabled": true,
  "args": [{"name": "query", "type": "string", "required": true}],
  "steps": [
    {"ref": "primitive:focus", "kwargs": {"target": "{default_browser}"}},
    {"ref": "primitive:press", "kwargs": {"combo": "ctrl+t"}},
    {"ref": "primitive:press", "kwargs": {"combo": "ctrl+l"}},
    {"ref": "primitive:type",  "kwargs": {"text": "{query}"}},
    {"ref": "primitive:press", "kwargs": {"combo": "enter"}}
  ]
}

At dispatch time, commands/template.py walks each step's kwargs and replaces {name} tokens using a merged context of {default_browser: …} + the arg values the LLM passed. Unknown placeholders raise TemplateError — the dispatcher halts the workflow instead of typing a literal {foo} into your window.

Step ref values use primitive:<name> or command:<name>. Workflows can build on top of existing commands; commands cannot reference workflows (keeps the dependency graph acyclic).

5. What the LLM sees

The LLM receives only the output of registry.all_llm_visible(), which returns entries where enabled=True, llm_only=True, and internal=False. That list is exactly:

  • every enabled user-defined command (origin="command")
  • every enabled user-defined workflow (origin="workflow")
  • no_match — the single non-command tool, used when nothing fits

The system prompt is a short intent-matcher: "pick one tool whose description or phrases best match the transcript; if nothing fits, call no_match." No few-shot examples, no shortcut cheat-sheet — because tool descriptions already carry that information.

6. Creating a command

  1. Go to the dashboard → click + New command.
  2. Pick a snake_case name (e.g. focus_editor).
  3. Fill in a short description. This goes to the LLM verbatim.
  4. Add synonyms — one per line. The LLM sees them appended to the description as Phrases:.
  5. Pick a primitive from the dropdown and supply its kwargs as JSON.
  6. Click Save. The registrar re-runs under the reload lock; the LLM sees the new tool on the next utterance — no daemon restart required.

7. Creating a workflow

  1. Click + New workflow.
  2. Name, description, synonyms (use {arg} placeholders to hint at templated forms).
  3. Args: JSON array of {name, type, required, description}. The LLM's tool schema is built from this.
  4. Steps: JSON array of {ref, kwargs}. Refs are primitive:press, primitive:focus, etc.
  5. Use {placeholder} inside any string kwarg to substitute at dispatch time.
  6. Save. Hot-reloads the same way commands do.

8. Runtime config

The Config section edits three sections of config.toml: [llm] (endpoint, model id, default browser, timeout), [audio] (PortAudio device index), and [transcription] (whisper model size, min confidence).

Saving calls update_user_config() which rewrites the file atomically (*.tmp + os.replace) and only accepts a hardcoded allow-list of keys to prevent the UI from clobbering [hotkey], [vad], etc.

Audio device changes and whisper model changes need a daemon restart. Click the Restart daemon button: the /restart route spawns a detached python -m voice_commander process, sleeps ~500 ms so the HTTP response can flush, then os._exit(0)s the current process.

9. Files on disk

  • commands.json — user-owned command catalog. Seeded from commands.default.json on first run.
  • workflows.json — user-owned workflow catalog. Seeded from workflows.default.json.
  • config.toml — runtime config. Hand-edit or use the Config form.
  • src/voice_commander/tools/primitives.toml — sidecar metadata for primitive functions. Not user-editable via the UI (primitives are code, not data).

10. Live UI sync

The daemon publishes command_saved / command_deleted / workflow_saved / workflow_deleted events on the internal EventBus. They stream out of GET /events as Server-Sent Events. Every open dashboard tab subscribes and re-fetches the relevant fragment so edits on one machine show up instantly on the other.

11. What this architecture removed

  • Agentic fallback loop. Previously a miss triggered a multi-turn "observe → act → observe" chain (up to 6 LLM calls). Deleted entirely. Match or miss, one call.
  • Legacy semantic verbs. close, close_window, minimize, maximize, last, summon_commander, mute, done, ask_user are disabled in primitives.toml. Equivalent behaviour is now expressed as commands (e.g. the starter pack's close_window = press(alt+f4)).
  • Perception tools. get_focused_window, list_windows, get_clipboard, list_processes are disabled — the LLM never observes live desktop state; commands run deterministic plans based on the transcript alone.
  • Few-shot prompt + shortcut cheat-sheet. Tool descriptions + synonyms do the same job with less prompt real estate.
